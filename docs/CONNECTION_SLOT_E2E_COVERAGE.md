# Connection-slot E2E coverage

This inventory maps the required scenario groups in the [implementation plan](CONNECTION_SLOT_DEFINITIONS_IMPLEMENTATION_PLAN.md#required-e2e-regression-matrix) to named Electron tests. These tests use isolated profiles and real UI/preload/IPC/persistence. Authentication, HTTP and external package-manager processes are simulated at their boundaries. They do not establish live environment acceptance or published catalog intake compatibility.

Verification status (2026-10-14): **Complete for the automated matrix.** The complete Electron run executed all **121 tests**: 120 passed and one newly added restart case hit a closed-window discovery race in the test helper. The helper now ignores windows closed during discovery; the affected case passed both a focused rerun and `pnpm exec playwright test --last-failed`. All 121 distinct scenarios are verified, with no skipped tests or unresolved failures. The updated marketplace Install-button workflow also passed its focused rerun. **286 targeted unit/type/validator/runtime/protocol tests**, application type checks, the Electron build and the new strict E2E type check passed. Light, narrow dark and long-purpose picker renders were inspected. Live acceptance and release dependencies remain pending.

## Runtime bounds found by the matrix

Count/range launches already bounded assignments by the declared maximum, but direct runtime reassignment could retain excess indexes. Reassignment now applies the same truncation before compatibility validation and notifications. Explicit contracts retain their existing atomic excess-slot rejection. This fixes maximum enforcement without changing integer/min-max default resolution, legacy combinations, null ordering or picker behavior. A focused manager test verifies discarded IDs are never resolved.

## Scope and remaining release work

The supported archive path extracts tar/gzip archives; this repository does not expose a separate ZIP installer. Tests exercise the real supported extractor and npm/local paths. Native/serialized Supabase slot mapping also has registry unit/integration coverage; external catalog storage, intake policies and publication remain separate release dependencies, not a live service result from these tests.

The release introducing slots, corresponding `minAPI`, coordinated app/types/validator publication and live mixed-environment smoke test remain pending. Automated coverage does not substitute for those items.

Run the full suite with `pnpm exec playwright test` after building the Electron app. Type-check the new matrix/workflow tests with `pnpm exec tsc -p tests/e2e/tsconfig.connections.json`; application type checks and targeted manager/validator/protocol checks remain separate.
